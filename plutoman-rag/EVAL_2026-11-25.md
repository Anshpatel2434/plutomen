# Evaluation of `fix/chat-follow-up-narrowing` — and a regression already on `main`

Measured 25 Nov 2026 against this branch (`927196d`), branched from `main` at
`9c1bac6`. **Read the second half before merging:** the golden set scores much
worse than it did in October, and the cause is not in this branch.

## What this branch changes

| Commit | |
|---|---|
| `fdbe7e1` | a question that stands on its own is no longer narrowed by the earlier turns of its chat |
| `ba90018` | a report named by its bare number (`4562922674`) matches the stored `POID-…` id |
| `a4bf1ae` | a number the question calls a PO is left as a PO |
| `927196d` | "the OTHER Finolex job" excludes the report already discussed, as a filter rather than as words in the query |

The first and last are reached only from `POST /chat`. The middle two are in the
data engine and fire only on a bare number that **is** one of the tenant's
report ids.

## Results

Same harness and same graders as every previous round (`/search` for single
questions, `/chat` for the multi-turn cases), `CACHE_ENABLED=false`,
`VERIFY_ANSWERS=true`, mistral on the GPU.

| Set | October (round 6) | This branch |
|---|---|---|
| Golden, strict rules of the client PDF | **37/39** (1 blocked) | **27/39** (1 blocked) |
| Held-out v1, strict | **26/36** | **29/36** |
| — of which multi-turn | **1/3** | **3/3** |
| Held-out v2 | 26/36 | not finished (34/36 run; no resume, needs a fresh run) |

The October run was re-graded with today's grader, so the comparison is
like-for-like.

**Held-out v1 improves by 3**, and its multi-turn cases go from 1/3 to 3/3 —
those are the contrastive follow-ups ("the other … lot") that `927196d` fixes.
Both golden multi-turn cases (Q38, Q39) also pass; Q38 does **not** pass on
`main`.

## The concern: ten golden cases that regressed before this branch

Failing in October: Q18, Q33 (Q22 blocked).
Failing now, additionally: **Q02, Q10, Q13, Q19, Q26, Q27, Q32, Q35, Q36, Q40.**

Every one is a single-turn `/search` case, which this branch cannot affect:

1. None of the 40 golden questions is altered by `canonicalReportIds` — checked
   against all 11 report ids; 0 rewrites. It is the only change on this branch
   that `/search` reaches at all.
2. On `/search` the new `excluded` argument is empty, so the answer prompt is
   byte-identical, and no exclusion filter is added, so the SQL is identical.
3. The chat-turn changes do not execute on `/search`.
4. Where the branch *does* act (Q38, Q39), both cases pass.

So these ten regressed somewhere in the November work that landed in `main`
through PR #1, not here.

What the failures look like:

- **Q40 — the prompt-injection refusal now leaks `system instructions:`.**
  Treat this as the urgent one: it is a safety case, not an accuracy case.
- **Q26, Q27 (CLARIFY).** Both should ask which report is meant when the
  question names a vendor that has several. They now answer instead — and Q26
  answers with a PO number under the name of a different field.
- **Q13.** States 2 failing tests where 4 are recorded.
- **Q10, Q32.** Values missing, and citations listing reports the answer does
  not use (the strict rules score a wrong-document citation as a fail).
- **Q02, Q19.** A date and a time missing from otherwise correct answers.
- **Q35, Q36.** A conflict that must be left unresolved is resolved; a required
  observation is left out.

A plausible common thread is that questions now answered from the computed
tables bypass the behaviour the golden set asks for (clarifying, abstaining,
leaving a conflict open) — but that is a reading of the failures, not a
diagnosis, and it should be confirmed before anything is changed.

**Latency**: mean 61.4 s per held-out question, against 16.6 s in October.

## What has NOT been established

- **No run of `main` itself.** The attribution above is a code-path argument
  plus the two cases that differ, not a measurement. The clean way to settle it
  is to run the golden set against `main` (`9c1bac6`) and confirm it also scores
  around 27/39. That is ~40 minutes of GPU time.
- **Held-out v2 is unfinished** (34 of 36). Two cases are missing, so there is
  no v2 number for this branch.
- The ten failures above have not been investigated case by case.

## Reproducing

The harness, the golden questions, the gold answers and the frozen held-out
sets are the client's material and are deliberately **not** in this repository.
The run outputs are kept locally for the same reason (they contain the
questions verbatim): `eval_runs_2026-11-25/` in the working copy, untracked.

```bash
CACHE_ENABLED=false docker compose -f docker-compose.yml -f docker-compose.gpu.yml --profile app up -d
python <harness>/eval_answers.py  out.json     # golden, 40 questions
python <harness>/golden/golden_strict.py out.json
```
